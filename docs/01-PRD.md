# 校园闲置物资循环 AI 平台 · 产品需求文档（PRD）

版本：v1.0　编写日期：2026-10-31　赛道：传智杯 AI 创新应用挑战赛

## 1. 选题归属（对齐官方赛题话术）

本项目命中官方十大黄金选题方向中的：

- **方向 6｜校园/垂直社区全栈 MVP 平台**（主归属）：基于公开数据与标准数据格式，AI 快速搭建动态图表大盘 + 大模型趣味解读。本项目的「环保看板」即该方向的 ECharts 大盘 + AI 生成环保报告。
- **方向 2｜场景化轻量 RAG 知识库**（次归属）：垂直校园场景的高交互智能检索。本项目的「供需智能匹配」即校内闲置库存的向量语义检索。
- **方向 3｜多模态创意与微工具工坊**（辅助）：VLM 图片识别 + 文案生成 + 估价，构成发布环节的微型 SaaS 工具。

技术取向遵循命题原则：**高频 API 组合、重前端交互与视觉、避免低级硬件死磕、强调 10 分钟极速复现**。

## 2. 问题定义

### 2.1 痛点

| 角色 | 痛点 | 现状替代方案的缺陷 |
|---|---|---|
| 毕业生 | 离校前大量教材、被褥、台灯、小家电带不走，扔掉可惜、卖又懒得定价拍照 | 闲鱼需自行定价、写文案、承担邮费；校内群消息刷屏、无留存 |
| 新生/困难生 | 教材与生活用品重复采购，一学期额外支出 300–800 元 | 商业平台无法定向获取「免费捐赠」资源 |
| 学院/资助中心 | 帮扶工作缺少可量化的物资流转台账 | Excel 手工登记，无环保数据可对外展示 |

### 2.2 与商业二手平台的差异定位

1. **限定本校**：同校身份 + 线下自提，无物流、无资金往来，规避交易风险。
2. **双通道流转**：低价转售 / 公益捐赠，同一套发布流程分流。
3. **帮扶优先**：捐赠物资对通过审核的困难学生优先曝光与申领。
4. **公益台账**：捐赠记录、电子感谢信、环保量化数据可导出，供学院公示使用。

### 2.3 范围边界（明确不做）

- 不做在线支付、担保交易、物流对接；成交为线上达成意向 + 线下自主交割。
- 不做实名认证对接、不做信用分体系。
- 不做自研模型或算法研究，全部使用商用大模型 API 的应用层编排。

## 3. 用户与角色

| 角色 | 说明 | 关键权限 |
|---|---|---|
| 普通在校生 | 默认角色 | 发布、浏览、申领、收藏、私信 |
| 毕业生 | 同普通用户，仅发布动机不同（打包清仓） | 同上 |
| 帮扶生 | 提交困难申请、由管理员审核通过 | 捐赠物资优先展示、申领捐赠物资 |
| 管理员 | 固定账号 | 审核帮扶申请、处理违规举报、查看统计看板 |

## 4. 功能需求

### 4.1 核心 AI 能力（阶段 3）

**F-AI-1 物品智能发布辅助**
输入：1 张物品图片 + 一句口语化描述（如「高数课本 上下册 写过几页」）。
输出：类别、成色等级（95新/9成新/8成新/可用）、规范标题、通顺商品文案、参考定价区间（`{low, high, suggested}`）、标签数组。
要求：AI 结果全部字段**可人工编辑覆盖**；识别失败时降级为纯文本生成，不阻断发布。

**F-AI-2 供需智能匹配（RAG 语义检索）**
输入：自然语言查询（「有没有便宜的高数教材」「宿舍不占地方的小台灯」）。
处理：查询向量化 → 与物品向量库做余弦相似度召回 Top-K → 捐赠物资加权置顶 → 交给 LLM 做一段自然语言推荐说明。
输出：命中物品列表（带相似度分档）+ AI 导购语。
要求：搜索无结果时给出放宽条件的建议，而非空白页。

**F-AI-3 违规内容审核**
在发布提交前对文本 + 图片做分类判定，输出 `{pass, category, reason}`。
拦截范围：违禁品、危险品、药品、活体动物、疑似非校内来源的大额商品、涉黄涉政。
要求：命中即阻断发布并展示原因；判定结果与理由落库留痕。

**F-AI-4 捐赠标签与电子感谢信生成**
捐赠物资自动生成公益标签（如「教材援助 · 已流转 1 位学弟」）；申领完成后按捐赠人、物品、受赠人（可匿名）生成正式而不煽情的感谢信，支持在线查看与导出。

### 4.2 基础业务（阶段 2）

注册/登录（会话保持）；发布表单（图片上传 + 描述 + 模式选择）；首页列表（分类 / 成色 / 模式 / 关键词筛选）；物品详情；收藏；申领与状态流转（待处理 → 已同意 → 线下完成 / 已取消）；我的发布 / 我的收藏 / 我的申领；捐赠台账列表；帮扶申请入口；物品站内信（私信）。

### 4.3 数据看板（阶段 4）

平台累计流转件数、转售/捐赠占比、按类别分布、按月趋势、折算节约纸张与减碳量、受益人数。图表用 ECharts；「一键生成环保报告」调用 LLM 输出可下载的图文报告；台账支持 CSV 导出。

## 5. 非功能需求

| 项 | 要求 |
|---|---|
| 复现性 | 新机器 3 条命令内跑起来；`npm run seed` 一键灌入演示数据；`.env.example` 列出全部环境变量 |
| 性能 | 单次 AI 调用 P95 < 8s，超时 15s 熔断并降级；列表页首屏 < 1s |
| 安全 | 密码加盐哈希（scrypt/bcrypt）；服务端校验登录态；API Key 只在服务端使用，绝不下发浏览器；上传文件类型与大小白名单；SQL 全部参数化 |
| 可观测 | 每次 AI 调用的 prompt、原始响应、模型名、耗时写入 `ai_call_logs` 表，可导出为提交材料 |
| 兼容 | Chrome/Edge 最新两版，移动端响应式 |

## 6. 验收标准（Definition of Done）

1. 毕业生路径：拍照 → AI 生成文案与估价 → 人工修改 → 发布成功 → 被语义搜索命中 → 有人申领 → 标记线下完成。
2. 捐赠路径：选择公益捐赠 → AI 生成捐赠标签 → 帮扶生优先看到 → 申领 → 生成感谢信 → 台账与看板数据同步 +1。
3. 违规路径：提交「处方药」描述 → 被拦截并展示原因 → 管理员端可见留痕记录。
4. 看板路径：管理员登录 → 看到全部统计与图表 → 一键生成环保报告 → 导出 CSV。
5. 全程 Git 提交历史细粒度、可对应到各轮 AI 对话。
