# 数据库设计（SQLite）

## 1. ER 关系

```
users 1───n items
users 1───n favorites n───1 items
users 1───n applications n───1 items        （申领：转售与捐赠共用）
applications 1───0..1 donations 1───1 letters（捐赠闭环）
users 1───n aid_applications
items 1───n messages（站内信挂在物品下）
users 1───n ai_call_logs（AI 调用留痕，ref_item_id 可空）
items 1───1 embedding（向量存 items 表 BLOB 列）
```

## 2. 表与字段

### users
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK AUTOINCREMENT | |
| username | TEXT | UNIQUE NOT NULL | 登录名，学号或自定义 |
| password_hash | TEXT | NOT NULL | scrypt 输出 |
| salt | TEXT | NOT NULL | 每用户随机盐 |
| nickname | TEXT | NOT NULL | 展示名，捐赠场景可用「某学长」 |
| college | TEXT | | 学院 |
| grade | TEXT | | 年级，如 2023 / 毕业班 |
| role | TEXT | NOT NULL DEFAULT 'user' | user / admin |
| is_aid_approved | INTEGER | NOT NULL DEFAULT 0 | 帮扶资格：0 未申请 / 1 通过 / 2 待审 / 3 驳回 |
| letter_anonymous | INTEGER | NOT NULL DEFAULT 1 | 感谢信署名：1 匿名（默认）/ 0 可署昵称；学院与年级永不出现在信中 |
| created_at | TEXT | NOT NULL DEFAULT datetime('now','localtime') | |

### items
| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | INTEGER | PK | |
| owner_id | INTEGER | FK users, NOT NULL | 发布人 |
| title | TEXT | NOT NULL | 最终展示标题（可能来自 AI） |
| raw_desc | TEXT | | 用户原始口语描述（保留用于对比 AI 改写） |
| ai_desc | TEXT | | AI 生成文案 |
| category | TEXT | NOT NULL | textbook / bedding / stationery / appliance / daily / clothing / other |
| condition_level | TEXT | | 95新 / 9成新 / 8成新 / 可用 |
| mode | TEXT | NOT NULL | sale / donate |
| price | REAL | sale 必填，donate 为 0 | 用户最终定价 |
| ai_price_low | REAL | | AI 参考区间下限 |
| ai_price_high | REAL | | AI 参考区间上限 |
| ai_tags | TEXT | | JSON 数组字符串 |
| ai_edited | INTEGER | DEFAULT 0 | 0 未采纳 / 1 直接采纳 / 2 采纳后修改（答辩可讲「人机协同率」） |
| image_path | TEXT | | /uploads/xxx.jpg |
| donate_tag | TEXT | | AI 生成的公益标签 |
| status | TEXT | NOT NULL DEFAULT 'listed' | listed / reserved / completed / removed |
| violation_flag | INTEGER | DEFAULT 0 | 0 正常 / 1 人工判定违规并下架 / 2 待人工复核（AI 审核故障时放行） |
| violation_reason | TEXT | | 审核依据：类别 + 理由，或「AI 审核不可用（超时/接口错误）」 |
| embedding | BLOB | | text-embedding-v3 向量（float32 序列化） |
| embedded_at | TEXT | | 向量生成时间，文案变更后置空重算 |
| view_count | INTEGER | DEFAULT 0 | |
| created_at | TEXT | DEFAULT (datetime('now','localtime')) | |

索引：`idx_items_category(category, mode)`、`idx_items_owner(owner_id)`、`idx_items_status(status)`。

`embedding` 固定 1024 维 float32，单条 4096 字节；`embedded_at` 为空的行视为「待补算」，由列表页在响应结束后串行补算（见 `docs/04-AI接口契约.md` R12 一节）。

**可见性约定**：首页列表、`/donate`、语义检索、向量补算统一用 `status='listed' AND violation_flag <> 1`。只排除 `1`（人工确认违规）而保留 `2`（待复核），是因为 `2` 的含义是「AI 审核故障时已放行、等人工看一眼」——先掐掉就等于审核故障阻断发布，与 R13 的容错设计相悖。

### favorites
`user_id INTEGER`、`item_id INTEGER`、`created_at TEXT`；`PRIMARY KEY(user_id, item_id)`。

### applications（申领单，转售与捐赠共用）
| 字段 | 类型 | 说明 |
|---|---|---|

### donations（捐赠台账）
| 字段 | 类型 | 说明 |

| item_id | INTEGER | |

### letters（电子感谢信）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER | PK |
| donation_id | INTEGER | FK donations，**UNIQUE**：一笔捐赠只有一封信，幂等的落点 |
| content | TEXT | 信件正文（含落款，200-300 字） |
| receiver_anonymous | INTEGER | 生成时的署名口径：1 匿名（信中自称「一位同学」）/ 0 可署昵称 |
| source | TEXT | ai / template：模型生成，或模型不可用时按平台模板兜底 |
| issued_at | TEXT | 首次生成时间 |

写入用 `INSERT OR IGNORE`，靠 `donation_id UNIQUE` 保证同一笔捐赠并发请求也只落一行；`source='template'` 的信在用户显式点「升级为 AI 版本」时原地更新为 `ai`，不新增行。

### messages（站内信）
`id`、`item_id`、`from_user_id`、`to_user_id`、`content`、`read_flag INTEGER`、`created_at`。索引 `idx_msg_pair(item_id, from_user_id, to_user_id)`。

### aid_applications（帮扶资格申请）
`id`、`user_id`、`reason TEXT`、`proof_note TEXT`（说明材料，Demo 不传真实证件）、`status TEXT`(pending/approved/rejected)、`reviewed_by INTEGER`、`created_at`、`reviewed_at`。

### ai_call_logs（AI 调用留痕 —— 比赛证据链，必须保留）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| feature | TEXT | analyze / search / moderate / letter / report（环保报告，R18 起）/ embed / health |
| model | TEXT | 如 qwen-vl-max、text-embedding-v3 |
| user_id | INTEGER | 触发人 |
| ref_item_id | INTEGER | 关联物品，可空 |
| prompt_text | TEXT | **发给模型的完整 prompt 原文** |
| response_text | TEXT | **模型原始返回**（未加工） |
| parsed_result | TEXT | 解析后的 JSON |
| latency_ms | INTEGER | 耗时 |
| status | TEXT | ok / timeout / parse_error / api_error |
| created_at | TEXT | |

> 该表是省赛提交材料「AI 对话历史导出的 Prompt 历史快照」的直接来源，`GET /api/admin/ai-logs/export` 导出为 JSON/CSV 即可作为附件。

### reports（环保报告，R18）

| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| title | TEXT | 标题由服务端拼，不让模型起标题（避免把数字带歪） |
| content | TEXT | 模型正文。`verify_status='fail'` 时也留档，但页面不渲染 |
| model | TEXT | 生成用模型 |
| months | INTEGER | 统计窗口（默认 6，夹在 1–24） |
| char_count | INTEGER | 去空白字符数，用于核对「600-900 字」 |
| verify_status | TEXT | pass / fail —— **「不通过就不展示」落成数据，而不是页面里的 if** |
| verify_json | TEXT | 校验明细：未命中的数字、字数、白名单规模 |
| snapshot_json | TEXT | 生成时的数据快照，报告页的图与数字表都读它，不读实时数据 |
| payload_text | TEXT | 送进 prompt 的数据原文 = 数字白名单来源，可逐字复核 |
| created_by | INTEGER | 触发生成的管理员 |
| created_at | TEXT | |

> 为什么存一份 `payload_text`：报告里的每个数字都要能追溯到「它来自哪一行数据」。只存 `content` 的话，事后无法复现当时喂了什么。

## 3. 状态机

```
items:  listed ──有人申领并同意──> reserved ──线下交割确认──> completed
          │                            └──取消──> listed
          └──审核不通过 / 举报成立──> removed
applications: pending ──同意──> approved ──确认交割──> completed
              ├─ 拒绝 ─> rejected      └─ 任一方取消 ─> cancelled
aid_applications: pending ─> approved / rejected
```

## 4. 环保折算系数（`src/lib/green-factors.ts`）

| 类别 | 单件重量 kg | 说明 |
|---|---|---|
| textbook | 0.35 | 纸张再生产节约约 0.9 kg 标煤 |
| bedding | 2.5 | |
| stationery | 0.15 | |
| appliance | 1.2 | 按电子废弃物减碳 2.1 kg CO₂e/件 |
| daily | 0.4 | |
| clothing | 0.3 | |

减碳量 = Σ(件数 × 重量 × 0.8 kg CO₂e/kg) + 类别专属修正项。系数写死在配置文件并注明「参考值，用于 Demo 估算」，答辩时如实说明口径，不夸大为实测数据。

## 5. R20 新增的两张表（安全加固）

### `sessions` —— 会话可吊销

| 字段 | 类型 | 说明 |
|---|---|---|
| jti | TEXT PK | 令牌里的会话标识（UUID），每次登录都不同 |
| user_id | INTEGER | 外键 → users，级联删除 |
| created_at | TEXT | 签发时间 |
| expires_at | INTEGER | 过期时间（秒级时间戳），与令牌里的 `exp` 一致 |
| revoked_at | TEXT | 吊销时间，非空即失效（退出登录 / 踢下线） |
| user_agent | TEXT | 截前 200 字符，便于「哪台设备」排查 |

索引：`idx_sessions_user(user_id)`、`idx_sessions_exp(expires_at)`。

改这张表之前，令牌是 `userId.HMAC(userId)`：没有过期、没有吊销，退出登录只是删浏览器 cookie，偷到的令牌永久有效。现在 `getCurrentUser` 会 JOIN 一次 `sessions` 并检查 `revoked_at IS NULL AND expires_at > now`。

### `uploads` —— 图片归属

| 字段 | 类型 | 说明 |
|---|---|---|
| path | TEXT PK | `/uploads/<uuid>.jpg` |
| user_id | INTEGER | 上传者，外键 → users |
| created_at | TEXT | 上传时间 |
| used_item_id | INTEGER | 被哪件物品用上（发布成功后回填），为空即孤儿文件 |

索引：`idx_uploads_user(user_id, created_at)`。

文件名是 `randomUUID`，本身不含身份信息；「这张图是谁传的」只能靠这张表。发布接口因此能拒绝「拿别人的图片挂到自己物品上」，后续做孤儿文件清理也有依据（`used_item_id IS NULL AND created_at < 24h`）。
