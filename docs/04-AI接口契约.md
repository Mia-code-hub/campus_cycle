# AI 接口契约（阿里百炼 / DashScope）

统一约定：全部接口为 Next.js Route Handler（`src/app/api/ai/**`），**API Key 只在服务端读取**，浏览器不接触。请求与响应均为 JSON（图片以 multipart 或 base64 dataURL 传入）。每次调用写一条 `ai_call_logs`。

模型选型：
| 用途 | 模型 | 备注 |
|---|---|---|
| 图片识别 + 文案 | `qwen-vl-max` | 多模态，支持图 + 文 |
| 文本生成（导购/感谢信/报告） | `qwen-plus` | 成本与效果平衡 |
| 向量化 | `text-embedding-v3` | 1024 维，支持中文 |

调用方式：OpenAI 兼容端点 `https://dashscope.aliyuncs.com/compatible-mode/v1`，用官方 `openai` SDK 即可，减少自写 HTTP 的出错面。

## 1. `POST /api/ai/analyze` — 物品智能发布辅助

**请求**
```json
{
  "image": "data:image/jpeg;base64,...",
  "rawDesc": "高数课本 上下册 写过几页",
  "mode": "sale"
}
```
**响应 200**
```json
{
  "category": "textbook",
  "conditionLevel": "9成新",
  "title": "同济版《高等数学》上下册（第六版）",
  "aiDesc": "同济第六版高数上下册成套，内页仅有少量笔记，无缺页无水渍，适合大一新生打基础使用。",
  "priceRange": { "low": 12, "high": 25, "suggested": 18 },
  "tags": ["高等数学", "教材", "大一", "成套"],
  "donateTag": null,
  "modelUsed": "qwen-vl-max",
  "degraded": false
}
```
`mode:"donate"` 时 `priceRange` 为 null 且返回 `donateTag`（如「教材援助 · 让知识继续流转」）。

**降级策略**：图片不可用 → 仅用 `rawDesc` 走纯文本生成并置 `degraded:true`；超时/解析失败 → 返回 502 `{ degraded:true, fallbackFields:[] }`，前端保留空表单让用户手填，**绝不阻断发布**。

**Prompt 要点**（`src/lib/ai/prompts.ts`）
- 系统角色：校园二手物品信息整理助手，禁止编造图片中不存在的品牌与版本。
- 强制输出 JSON Schema，字段枚举值写死（category 7 类、conditionLevel 4 档）。
- 定价要求：给出「校内可接受」的低价区间，说明依据为成色与品类常识，**不虚构历史成交数据**。
- 少样本示例 2 条（教材、台灯），提升格式稳定性。

> 关于「参考校内历史成交数据」：真实实现是把 `items` 表同 `category` 的已成交 `price` 做均价，拼进 prompt 作为上下文。阶段 3 先接「同类目历史均价」，答辩时这就是一个轻量 RAG 之外的数据增强例子。

## 2. `POST /api/ai/search` — 供需语义匹配

**请求** `{ "query": "有没有便宜点的高数课本", "topK": 20 }`
**响应**
```json
{
  "guide": "为你找到 3 本高等数学教材，其中 1 本为公益捐赠、可免费申领……",
  "items": [
    { "id": 12, "title": "...", "mode": "donate", "price": 0,
      "similarity": 0.83, "matchLabel": "高度匹配" }
  ]
}
```
**处理链**：`query → embed → 载入 items.embedding → 余弦相似度 → 业务加权（donate+0.15、帮扶生对 donate 强制置顶、status=listed 过滤）→ Top-K → qwen-plus 生成 guide`。
**空结果**：返回 `items:[]` + `guide` 为放宽建议（换关键词/看全部分类）。
**性能**：物品量 < 5000 时全表向量在内存计算即可（约 20MB），**不引入向量数据库**——这是刻意的架构取舍，写进技术文档的「架构设计」章节：避免过度工程，保证 10 分钟复现。

## 3. `POST /api/ai/moderate` — 违规内容审核

**请求** `{ "title": "...", "desc": "...", "image": "data:..." }`
**响应** `{ "pass": false, "category": "prohibited", "reason": "描述涉及处方药品，校内平台禁止流通", "confidence": 0.92 }`
枚举 `category`：`ok` / `prohibited`（违禁品）/ `dangerous`（危险品）/ `medical`（药品医疗器械）/ `animal`（活体动物）/ `indecent`（不良内容）/ `offcampus`（疑似校外商业倒卖）。
**兜底**：审核接口失败时**默认放行但标记 `violation_flag=2` 待人工复核**，不可因审核故障阻断正常发布（写进文档作为容错设计说明）。

---

## 4. `POST /api/ai/letter` — 捐赠感谢信

**请求** `{ "donationId": 5 }`（服务端自查台账，不接受前端传入的隐私字段）
**响应** `{ "content": "……", "receiverAnonymous": true }`
**风格约束**：正式、平视、不煽情、不暴露困难生身份与任何证明材料信息；200–300 字；落款为「校园闲置循环平台」+ 日期。

## 5. `POST /api/ai/report` — 环保报告生成（阶段 4）
输入统计聚合结果（服务端计算，不接受前端传值），输出 Markdown 图文报告，含数据事实 + 一句结论；LLM 只负责措辞，**所有数字来自 SQL 聚合**，防止模型编造数据（这是可复现性论证的加分点）。
