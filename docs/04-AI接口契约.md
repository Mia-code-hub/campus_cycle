# AI 接口契约（阿里百炼 / DashScope）

统一约定：全部接口为 Next.js Route Handler（`src/app/api/ai/**`），**API Key 只在服务端读取**，浏览器不接触。请求与响应均为 JSON（图片以 multipart 或 base64 dataURL 传入）。每次调用写一条 `ai_call_logs`。

模型选型：
| 用途 | 模型 | 备注 |
|---|---|---|
| 图片识别 + 文案 | `qwen-vl-max` | 多模态，支持图 + 文 |
| 文本生成（导购/感谢信/报告） | `qwen-plus` | 成本与效果平衡 |
| 向量化 | `text-embedding-v3` | 1024 维，支持中文 |

调用方式：OpenAI 兼容端点 `https://dashscope.aliyuncs.com/compatible-mode/v1`，用官方 `openai` SDK 即可，减少自写 HTTP 的出错面。

## 1. `POST /api/ai/analyze` — 物品智能发布辅助

**请求**
```json
{
  "image": "data:image/jpeg;base64,...",
  "rawDesc": "高数课本 上下册 写过几页",
  "mode": "sale"
}
```
**响应 200**
```json
{
  "category": "textbook",
  "conditionLevel": "9成新",
  "title": "同济版《高等数学》上下册（第六版）",
  "aiDesc": "同济第六版高数上下册成套，内页仅有少量笔记，无缺页无水渍，适合大一新生打基础使用。",
  "priceRange": { "low": 12, "high": 25, "suggested": 18 },
  "tags": ["高等数学", "教材", "大一", "成套"],
  "donateTag": null,
  "modelUsed": "qwen-vl-max",
  "degraded": false
}
```
`mode:"donate"` 时 `priceRange` 为 null 且返回 `donateTag`（如「教材援助 · 让知识继续流转」）。

**降级策略**（任何一步失败都不阻断发布）：
1. 图片可用且 `VLM_MODEL` 具备视觉能力 → 图 + 文一起判断，`degraded:false`。
2. 无图片 / 视觉模型不可用（如只配了 DeepSeek，无视觉模型）→ 仅用 `rawDesc` 走纯文本生成，`degraded:true`。
3. 识图调用失败（超时 / 401 / 返回乱码）→ 自动用文本模型再试一次，成功则 `degraded:true`。
4. 全部失败 → 502 `{ degraded:true, fallbackFields:[], message:"AI 暂不可用，请手动填写" }`，前端保留空表单让用户手填。

枚举白名单在服务端二次校验：非法 `category` 归 `other`、非法 `conditionLevel` 归 `可用`；`title` 与 `aiDesc` 同时为空视为 `parse_error`（不落脏数据）。

**通道选择**：`client.ts` 按模型名前缀路由 —— `deepseek-*` 走 DeepSeek 官方端点，其余走百炼；两个通道各自读 `DEEPSEEK_API_KEY` / `DASHSCOPE_API_KEY`，换模型只改 `.env.local`。

**Prompt 要点**（`src/lib/ai/prompts.ts`）
- 系统角色：校园二手物品信息整理助手，禁止编造图片中不存在的品牌与版本。
- 强制输出 JSON Schema，字段枚举值写死（category 7 类、conditionLevel 4 档）。
- 定价要求：给出「校内可接受」的低价区间，说明依据为成色与品类常识，**不虚构历史成交数据**。
- 少样本示例 2 条（教材、台灯），提升格式稳定性。

> 关于「参考校内历史成交数据」：真实实现是把 `items` 表同 `category` 的已成交 `price` 做均价，拼进 prompt 作为上下文。阶段 3 先接「同类目历史均价」，答辩时这就是一个轻量 RAG 之外的数据增强例子。

**定价上下文（R11）**：每次 analyze 前用一条 `GROUP BY category` 查出各类目「已完成 + 转售 + price>0」的 `count/avg/min/max`，拼成「定价参考」段；某类目样本 < 3 时改用 `src/lib/ref-price.ts` 的内置经验区间（教材 8–30 元、小家电 15–60 元等），并注明是经验值。**模型只负责在区间内微调，不得编造历史成交。**
输出侧再做一次校验：`priceRange` 数字转整数、`low/high` 颠倒自动纠正、`suggested` 越界收敛到区间内、结构不成立整段丢弃；`priceReason` 截 40 字。
`mode:"donate"` 不查定价、不输出 `priceRange`，改为生成 8–16 字 `donateTag`（不含价格、不用「贫困/资助」等标签化词）。

## 2. `POST /api/ai/search` — 供需语义匹配

**请求** `{ "query": "有没有便宜点的高数课本" }`（query ≤ 100 字；Top-K 固定 8，由服务端决定，避免前端要多少给多少）
**响应**
```json
{
  "ok": true,
  "query": "有没有便宜点的高数课本",
  "engine": "vector",
  "degraded": false,
  "reason": null,
  "guide": "最贴合的是高等数学上册，有笔记、8成新、免费公益捐赠……",
  "count": 8,
  "items": [
    { "id": 134, "title": "高等数学 上册（有笔记）", "mode": "donate", "price": 0,
      "similarity": 0.674, "score": 1.124, "matchLabel": "较匹配" }
  ]
}
```
**处理链**：`query → embed（text-embedding-v3, 1024 维）→ 载入 status='listed' 且 embedding 非空的物品 → 余弦相似度 → 业务加权 → 排序取 Top-8 → qwen-plus 生成 60-100 字导购语`。

**业务加权**（`src/lib/search-score.ts`，与 `/donate` 共用 `donate-boost.ts` 里的帮扶规则）：
- 捐赠物品 `+0.15`；`is_aid_approved=1` 的帮扶生再加 `+0.30`，所以帮扶生看到的相关捐赠会明显前置。
- **加权只对 `similarity ≥ 0.5` 的结果生效**。实测把门槛去掉后，「枕头/被褥」这类无关捐赠会被 +0.45 顶到教材前面，相关性反而崩；低于门槛的物品照常出现在结果里，只是不享受加权。
- `similarity` 原样返回给页面显示百分比，`score` 只用于排序，不会把「相关」标成「高度匹配」。
- `matchLabel`：`≥0.75 高度匹配` / `≥0.6 较匹配` / 其余 `相关`。

**降级**：embedding 调用失败（key 失效、超时、维度异常）→ 自动退回 2-gram 关键词召回，响应 `engine:"keyword", degraded:true`，此时 `similarity` 为 `null`（前端不显示百分比）；导购语生成失败则 `guide` 为空字符串，只显示结果卡片。**搜索页任何情况下都不空屏、不报错页。**

**空结果**：后端返回 `items: []`、`guide: ""`（不给模型空转），页面显示放宽建议词、`/donate` 入口与发布入口。

**性能**：物品量 < 5000 时全表向量在内存计算即可（1024 维 × 8KB/件），**不引入向量数据库**——这是刻意的架构取舍：避免过度工程，保证 10 分钟复现。

### 向量化与补算（R12）

- `src/lib/ai/embed.ts`：`buildItemEmbedText` 把 `title + ai_desc + raw_desc + 类别中文名/枚举 + 成色 + ai_tags` 拼成一段文本再嵌入；向量 `Float32Array → Buffer` 写 `items.embedding`，同时写 `embedded_at`。
- 发布成功后用 Next 的 `after()` 在**响应结束之后**再算向量：用户看到的是「发布成功」立刻返回，模型挂了也只是这件物品暂时没有向量。
- 首页列表渲染时对 `embedding IS NULL` 的在架物品串行补算（一次 3 件，进程内互斥，失败后 60s 冷却），不阻塞响应。
- 文案变更后应调用 `invalidateEmbedding(itemId)` 置空 `embedded_at`，下次访问自动重算（当前项目还没有物品编辑入口，函数已备好给后续轮次接入）。
- 每次嵌入都落 `ai_call_logs`（`feature='embed'`），`response_text` 只记 `ok: n=1 dim=1024`，**不把 1024 个浮点写进日志**。

## 3. `POST /api/ai/moderate` — 违规内容审核

**请求** `{ "title": "...", "desc": "...", "image": "data:..." }`
**响应** `{ "pass": false, "category": "prohibited", "reason": "描述涉及处方药品，校内平台禁止流通", "confidence": 0.92 }`
枚举 `category`：`ok` / `prohibited`（违禁品）/ `dangerous`（危险品）/ `medical`（药品医疗器械）/ `animal`（活体动物）/ `indecent`（不良内容）/ `offcampus`（疑似校外商业倒卖）。
**兜底**：审核接口失败时**默认放行但标记 `violation_flag=2` 待人工复核**，不可因审核故障阻断正常发布（写进文档作为容错设计说明）。

## 4. `POST /api/ai/letter` — 捐赠感谢信

**请求** `{ "donationId": 5 }`（服务端自查台账，不接受前端传入的隐私字段）
**响应** `{ "content": "……", "receiverAnonymous": true }`
**风格约束**：正式、平视、不煽情、不暴露困难生身份与任何证明材料信息；200–300 字；落款为「校园闲置循环平台」+ 日期。

## 5. `POST /api/ai/report` — 环保报告生成（阶段 4）
输入统计聚合结果（服务端计算，不接受前端传值），输出 Markdown 图文报告，含数据事实 + 一句结论；LLM 只负责措辞，**所有数字来自 SQL 聚合**，防止模型编造数据（这是可复现性论证的加分点）。

SESSION_SECRET=change-me
