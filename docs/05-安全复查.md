# 全仓安全复查（R20）

> 复查时间：2026-11-15　｜　范围：`src/` 下 15 个 API 路由、6 个管理端页面、15 个服务层模块
> 本轮先出清单与改法，确认后按清单修复；第 13 节是**修复结果与实测证据**，未修项也列在那里。

## 1. 复查方法

- **静态**：逐文件通读 `server/{auth,db,items,search,retrieval,moderation,letters,reports,me,ai-logs,donations,item-state,password,vision-image}.ts` 与全部 `app/api/**/route.ts`。
- **检索**：`grep` 定位 `prepare(\`` 拼接、`dangerouslySetInnerHTML`、`fs.*` 读写、`ratelimit|throttle|attempts`、`headers()`。
- **动态**：4 组无害实测（只碰自己的账号与自己造的数据）——匿名调 AI 搜索、连续 8 次错误密码、上传 30MB 图片、请求不存在的路由。
- **边界**：`src/middleware.ts`、`next.config.ts` 的 `headers()`、`.gitignore`、`.env.example`。

## 2. 结论总表

| 类别 | 结论 | 需修复项 |
|---|---|---|
| 越权 / 权限 | 管理端与导出接口全部有 `role !== 'admin'` 复核；`/me` 系列全部按 `user_id` 过滤；但**详情页不校验物品状态**、**上传图片无归属** | 2 条 P1、2 条 P2 |

## 3. 越权 / 权限校验

### 3-1（P1）下架物品仍可完整访问
- **位置**：`src/app/items/[id]/page.tsx`、`src/server/items.ts` 的 `getItemDetail`
- **问题**：列表与搜索都过滤了 `status='listed' AND violation_flag<>1`，但详情页只按 id 查。管理员把违规物品下架后，任何人拿 `/items/{id}` 仍能看到正文、图片、发布者昵称与学院——「下架」只让它从列表消失，内容本身还在传播。
- **改法**：`getItemDetail` 增加 `includeHidden` 参数（默认 false），或在页面里 `if (item.violation_flag === 1 && !isOwner && user?.role !== 'admin') notFound()`。

### 3-2（P1）上传图片没有归属校验
- **位置**：`src/app/api/items/route.ts` 的 `imagePath` 校验、`src/app/api/upload/route.ts`
- **问题**：只用正则校验「形状像 `/uploads/<uuid>.jpg`」，没校验「这张图是不是你传的」。任何登录用户可以把别人的图片挂到自己发布的物品上（盗图、栽赃、把违规图挂到别人名下）。库里也没有 `uploads` 表记录归属。
- **改法**：建 `uploads(id, user_id, path, item_id, created_at)`，上传时落一行，发布时校验 `user_id` 匹配；读取时也按归属授权。

### 3-3（P2）403 与 404 混用造成存在性探测
- **位置**：`src/app/api/applications/[id]/route.ts`、`src/app/api/items/[id]/messages/route.ts`
- **问题**：不存在的 id → 404，无权 → 403，外部可凭状态码枚举「哪些申领单/对话存在」。感谢信那边做对了（`canViewLetter` 失败一律 `notFound()`），这两处没对齐。
- **改法**：无权一律返回 404。

### 3-4（P2）收藏与浏览量的边界
- `favorite` 接口对 `removed` 物品也接受；`getItemDetail` 每次请求无条件 `view_count + 1`，刷新即涨，本人也能刷。
- **改法**：收藏校验 `status='listed'`；浏览量按 `session + item` 24h 去重。

**已确认没问题**：4 个管理端接口 + 3 个导出接口都做了管理员复核；6 个 `/admin/*` 页面都有 `redirect`；私信靠 `getConversationPeer` 只放 approved 双方；`/api/ai/report` 只接受 `months`，数字全由服务端 SQL 聚合。

## 4. SQL 拼接

**结论：没有可注入点。**

- 全部走 better-sqlite3 预处理占位符。
- 5 处模板字符串拼 SQL 的地方（`items.ts`、`ai-logs.ts`、`donations.ts`）拼的都是代码内常量片段，值全部 `?`。
- `migrate.mts`、`seed.mts` 的表名来自硬编码常量，不接用户输入。

两处加固建议：
1. `page` 参数无上限（`page=1e9` 会触发大 offset 排序）→ 夹到 10000。
2. `feature` 白名单可保留，但以后若加「排序字段」类参数，**不要拼列名**，用 `const COLUMNS = { ... }` 映射。

## 5. 上传校验

### 5-1（P1）先收完整个 body 再判 5MB
- **位置**：`src/app/api/upload/route.ts`（`await req.formData()` 在前，`file.size` 判断在后）
- **实测**：以登录身份 POST 一个 30MB 的 jpg，接口**收完 30MB**（192ms）才回 `400 FILE_TOO_LARGE`。等于任何登录用户都能用大文件打内存。
- **改法**：先查 `content-length`（超 6MB 直接 413），再把 `req.body` 当流读、边读边累加，超 5MB 立刻 `reader.cancel()`；部署层（nginx `client_max_body_size`）兜底。

### 5-2（P1）只信扩展名和客户端声明的 MIME
- **问题**：`file.type` 由客户端给，改包就能把任意二进制存成 `.jpg`。当前打不出 RCE（Next 按扩展名给 `image/jpeg`），但等于开了个「域名可信的任意文件寄存处」。
- **改法**：读前 16 字节判魔数（JPEG `FF D8 FF` / PNG `89 50 4E 47` / WebP `RIFF....WEBP`），再用 `sharp().metadata()` 确认可解码。

### 5-3（P1）原图带 EXIF 落盘
- **问题**：手机拍的宿舍照可能带 GPS 经纬度与设备型号，而 `public/uploads/*` 是公开静态资源。
- **改法**：落盘前统一 `sharp().rotate().jpeg({ quality: 86 })` **重编码**——`rotate()` 按 EXIF 摆正，编码器默认丢弃元数据，顺手把 polyglot 文件洗成纯像素。

### 5-4（P2）无配额、无孤儿回收
- 传了不发布、物品下架后，文件永久留在 `public/uploads`（当前 12 个）。
- **改法**：挂 `uploads` 表做单用户配额与 24h 清理。

**已确认没问题**：`randomUUID()` 生成文件名（不用原文件名，无穿越无覆盖）、扩展名白名单、接口前置 `requireUser`。

## 6. 路径穿越

**结论：没有可利用点。**

全仓只有两处文件 IO：`moderation.ts` 读上传图、`upload/route.ts` 写上传图。读的入口先过 `/^\/uploads\/[a-f0-9-]+\.(jpg|jpeg|png|webp)$/i`（字符集不含 `.` 和 `/`，`$` 锚尾），再 `resolve(process.cwd(), 'public', ...)`——`../../`、`..%2f`、`//` 都进不去；写入的文件名与用户输入无关。

**加固（P2）**：`resolve` 之后补 `if (!abs.startsWith(UPLOAD_DIR + sep)) return ''`，把「靠正则」升级成「靠真实路径」，将来有人放松正则也不会立刻破防。

## 7. Cookie 配置

### 7-1（P0）令牌没有过期时间，也没有吊销机制
- **位置**：`src/server/auth.ts` 的 `signSession` / `verifySession`
- **问题**：`signSession` = `userId + "." + HMAC(userId)`，payload 里没有 `iat/exp/jti`，校验只验签名不看时间。后果：
  1. 偷到一个 cookie 就**永久**有效（7 天只是浏览器端 `maxAge`，攻击者自己发请求不受限）；
  2. 退出登录只删浏览器 cookie，**旧令牌照样能用**；
  3. 改密码踢不掉其他设备；
  4. 同一用户的令牌是**确定值**，无法区分设备、无法「仅退出其他设备」。
- **改法**：payload 换成 `base64url(JSON.stringify({ uid, exp, jti }))`，签名覆盖整段；加 `sessions(jti, user_id, expires_at, revoked_at)` 表，`getCurrentUser` 里 JOIN 一次判断未吊销未过期（可与现有 `SELECT users` 合并成一条 SQL）。

### 7-2（P1）`secure` 绑死 `NODE_ENV`
- HTTP 上以 production 启动 → 「登录成功但立刻掉线」；HTTPS 前置代理但 `NODE_ENV` 非 production → cookie 明文走一段。
- **改法**：改显式开关 `SESSION_COOKIE_SECURE`，并换 `__Host-session` 前缀（浏览器强制要求 Secure + Path=/ + 无 Domain）。

### 7-3（P2）密钥强度未校验
- 缺失会快速失败（做法正确），但没有强度校验，弱值不会被拦。
- **改法**：启动时校验长度 ≥ 32 且非示例值。

**已确认没问题**：全站写操作走 JSON POST，`req.json()` 解析不了 `application/x-www-form-urlencoded`，唯一用 multipart 的 `/api/upload` 也因 `SameSite=Lax` 不发跨站 cookie → CSRF 打不进来。

## 8. 错误响应泄漏

### 8-1（P1）状态机异常原文回给前端
- **位置**：`src/app/api/applications/[id]/route.ts`
- **问题**：返回 `"cancel 要求申领状态为 pending 或 approved，当前为 completed"`，等于把数据库状态字段与内部规则暴露出去。
- **改法**：对外固定「当前状态不支持该操作」，原文只进服务端日志。

### 8-2（P1）`/api/ai/health` 对任意登录用户返回模型名
- **位置**：`src/app/api/ai/health/route.ts`
- **问题**：返回 `model` 与 `kind`。`client.ts` 把上游 `e.message`（OpenAI SDK 报错常含 base_url / 模型名 / request_id）包进 `AiError`；虽然路由只回 `KIND_MESSAGE`，但 `kind + model` 已足以让人画出通道拓扑。
- **改法**：改为**仅管理员可调**（普通用户 403），并挂 AI 限流。真实探测能力保留——R9 的验收与录屏要用它证明通道通了，没必要为了保密把它阉成配置自检；把「谁能调」收掉即可。

### 8-3（P2）导出 JSON 带服务器路径
- `admin/ai-logs/export/route.ts` 的 `source: process.env.DATABASE_PATH` → 换成逻辑标识。

### 8-4（P2）透传供应商原始错误
- `admin/embeddings/rebuild/route.ts` 透传 `res.message` → 只回 `EMBED_FAILED`。

**已确认没问题**：15 个路由的 `await req.json()` 全有 try/catch；生产未捕获异常只回 digest；全站无 `dangerouslySetInnerHTML`，React 默认转义。

## 9. AI 接口限流

全仓 `grep -i "ratelimit|throttle|attempts"` 只命中「重试次数」，没有任何限流、配额、并发控制或缓存。

| 接口 | 鉴权 | 单次成本 | 实测/现状 |
|---|---|---|---|
| `POST /api/ai/search` | **无（匿名可调）** | 1 次 embedding + 1 次导购语 | 匿名直接 200：`engine=vector`、8 条结果、导购语 91 字 |
| `POST /api/ai/analyze` | 登录 | 最多 2 次（视觉失败退文本） | 6MB dataURL 上限，无次数限制 |
| `POST /api/ai/moderate` | 登录 | 最多 2 次 | 且 `POST /api/items` 内部再判一次 → 发布一件 = 4 次调用 |
| `POST /api/ai/letter` | 登录 | 最多 2 次 | 成功后幂等，风险中等 |
| `POST /api/ai/report` | 管理员 | 2 次 + 300s | 脚本循环即烧钱 |
| `GET /api/ai/health` | 登录 | 1 次 + 1 行日志 | 任何人可刷，顺手把 `ai_call_logs` 灌大 |

### 9-1（P0）`/api/ai/search` 匿名可用且每次调模型
- **改法**：匿名禁止调模型，只走关键词召回（`keywordSearch`），额度 3 次/分/IP；登录后恢复语义检索。

### 9-2（P0）登录无失败计数
- **实测**：连续 8 次错误密码，全部 401、每次 75–80ms、无退避无锁定。演示密码是 6 位数字、`admin` 用户名公开，字典爆破几分钟就中。
- **改法**：按 `username + ip` 记失败，5 次后指数退避，20 次锁 15 分钟；成功即清零。**这条建议排在 AI 限流之前做。**

### 9-3（P1）注册无频率限制 + 用户名可枚举
- `register` 的 409「用户名已被注册」直接确认该名存在。
- **改法**：5 次/小时/IP；冲突文案统一成「该用户名不可用」。

### 9-4（P1）缺统一 AI 限流层
- **改法**：写 `lib/rate-limit.ts`（进程内 Map + 滑动窗口，单机部署够用），按 `userId ?? ip + 路由` 计数：AI 类 10 次/分、30 次/时；在 `withAiLog` 外层统一 429 + `Retry-After`。多实例时换 SQLite 表/Redis，接口不变。

### 9-5（P2）缺缓存
- 同一 query / 同一图片 sha256 做 5–10 分钟缓存（校园里重复搜同一批关键词极常见），能砍掉大半调用。

## 10. 清单外但复查时看到的

- **P1｜全站没有安全响应头**：`next.config.ts` 无 `headers()`，缺 `X-Frame-Options`/`frame-ancestors`（可被 iframe 嵌套 → 点击劫持）、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、CSP。先上前四个；CSP 需保留 `img-src 'self' data:` 与 ECharts 的 inline style，建议先 `Report-Only` 跑一天再转正式。
- **P1｜`ai_call_logs` 不截断**：`lib/ai/log.ts` 全文入库，prompt 里含用户描述、感谢信上下文（昵称/学院）。既是 PII 长期留存，也是「用一张大图把库撑大」的路径。prompt/response 各截 32KB。
- **已确认没问题**：`.env.local`、`data/*.db`、`public/uploads/*` 全在 `.gitignore`；`FIRST_USER_IS_ADMIN=0`（不会出现「首个注册者变管理员」）；密码 `scrypt + 16 字节盐 + timingSafeEqual`；令牌签名比对用 `timingSafeEqual`。

## 11. 建议修复顺序

| 级别 | 项 |
|---|---|
| P0（5） | 会话过期 + 吊销 → 登录失败锁定 → 上传前置限长 → AI 限流层 → `/api/ai/search` 匿名降级 |
| P1（6） | 详情页下架物品 → 图片归属 → 魔数校验 + EXIF 重编码 → 错误文案收敛 → `ai/health` 降级 → 安全响应头 |
| P2 | 403/404 对齐、浏览量去重、导出路径、日志截断、`__Host-` 前缀、路径前缀二次校验 |

**可以放心**：SQL 拼接与路径穿越——不是「大致安全」，是按代码逐点确认每条用户输入都落在 `?` 或白名单里。真正会出事的是**会话令牌永不过期**与**AI 接口裸奔**。

## 12. 复现命令

```bash
# ① 匿名调 AI 搜索（应 200，engine=vector）
curl -s -X POST http://localhost:3000/api/ai/search \
  -H 'content-type: application/json' -d '{"query":"教材"}' | head -c 200

# ② 连续错误密码（8 次全 401，无 429 即无限流）
for i in $(seq 1 8); do
  curl -s -o /dev/null -w "%{http_code} " -X POST http://localhost:3000/api/auth/login \
    -H 'content-type: application/json' -d '{"username":"admin","password":"wrong'"$i"'"}'
done; echo

# ③ 30MB 上传（返回 FILE_TOO_LARGE 的耗时说明是「收完才拒」）
dd if=/dev/zero of=/tmp/big.jpg bs=1M count=30 2>/dev/null
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" -X POST http://localhost:3000/api/upload \
  -b "session=<你的 cookie>" -F "file=@/tmp/big.jpg;type=image/jpeg"
```

> ③ 需先登录拿 cookie；`admin` 的密码不写进仓库，演示时从 `.env.local` 或口述获取。
